# עדכון גרסה מתוך WhatsApp Auto Replay

0.4.1 (קוד 6) מוסיפה כרטיס גרסה ועדכונים בלשוניות הודעות והגדרות. בדיקה שקטה בפתיחת האפליקציה אינה פותחת מתקין. יש גם כפתור בדיקה ידנית, הערות גרסה, הורדה עם התקדמות ואישור מפורש להתקנה.

ההורדה יכולה להתבצע כשהמענה פעיל, אך ההתקנה דורשת לשמור שינויים, להשהות את המענה ולהמתין לסיום טיפול פעיל בהודעה. התנאי נבדק שוב אחרי אימות ה־APK. אין פתיחת מתקין אוטומטית בסיום הורדה או בחזרה מהגדרות הרשאה. Android מבקש הרשאת התקנה ממקור זה ואישור התקנה; אם בוטל, ניתן לנסות שוב.

ההגדרות, התבניות וההיסטוריה נשארות במכשיר. התנהגות שחזור התהליך הקיימת נשמרת: המענה אינו מופעל מחדש אוטומטית ובקשות קודמות אינן נשלחות שוב. לאחר עדכון יש לפתוח את האפליקציה ולהפעיל מענה לשיחות חדשות.

## אבטחה ונתונים

מסלול העדכון משתמש באינטרנט רק לבדיקת גרסה ולהורדת קובץ ציבורי. מסלול Meta API הקיים נשמר ופועל בנפרד. אין העברת שיחות, טלפונים, הודעות, אנשי קשר או הגדרות לשרת העדכונים. אין סודות או טוקן GitHub באפליקציה.

ערוץ ההורדה: `https://ofekpc.co.il/downloads/whatsapp-autoreplay/`. JSON נפרד לגרסה הראשית (`latest.json`) ולגרסת האבחון (`latest-diagnostic.json`). אין ערבוב בין שמות חבילות. ה־APK מוגש בסיומת `.apk.bin` כדי להשתמש בהגשת הקבצים הקיימת באתר; תוכנו זהה ל־APK ונשמר בטלפון בסיומת apk.

מאומתים HTTPS ללא redirects, כתובת קבועה, תקרת JSON של 16 KiB, תקרת APK של 80 MiB, גודל מדויק ו־SHA-256. לפני התקנה מאומתים שם החבילה, מספר ושם גרסה, גרסה חדשה יותר ואותה חתימת APK כמו החבילה המותקנת. קובץ חלקי נמחק; הורדה תקינה נשמרת לניסיון התקנה נוסף. FileProvider חושף רק את תיקיית העדכונים, בהרשאת קריאה זמנית.

## בנייה ופרסום

נדרש Gradle 8.13, JDK 21 ו־SDK 36 כפי שכבר הוגדרו בפרויקט. גרסאות Kotlin והספריות נשמרו.

```
gradlew testAutomaticDebugUnitTest testNoAccessibilityDebugUnitTest lintAutomaticDebug lintNoAccessibilityDebug assembleAutomaticRelease assembleNoAccessibilityRelease
```

יש לחתום את ה־APK הלא חתום באותו מפתח שבו נחתמה הגרסה המותקנת. גרסה 0.4.0 נארזה במקור כ־debug: הקובץ המקורי `debug.keystore` ממחשב הבנייה הוא הנדרש, לא מפתח debug חדש ממחשב אחר. אין לפרסם מפתח זה או להוסיף אותו ל־Git. אין להסיר את האפליקציה כדי לעקוף חוסר התאמה בחתימה, שכן פעולה זו מוחקת נתונים.

`Package-Update.ps1` מקבל APK חתום, את ה־APK שהותקן בעבר, תיקיית Android Build Tools ותיקיית פלט. הוא בודק את חתימות שני הקבצים, גרסה, חבילה, בדיקות ו־Lint לפני אריזת APK ודוח בדיקות. הוא מסרב למפתח חדש, שנמוך או APK debuggable. `package-app.py` הישן נותר לתיעוד אריזת 0.3.0 ואינו כלי שחרור העדכון.

כלי `tools/Publish-Update.ps1` מפרסם תחילה ל־Stage ולאחר אימות הורדה מלאה מאפשר Production. הוא מייצר את המניפסט ואוכף התאמת מקור, גרסה ו־hash.

לאחר חתימה תואמת יש לפרסם APK ו־SHA256SUMS ב־GitHub Release. באתר יש לבדוק את קובץ bin והמניפסט בסביבה מבודדת, להשוות hash של הורדה מלאה, ואז לפרסם קובץ גרסה בלתי משתנה ואת latest.json אחריו בהחלפה אטומית. יש לשמור מניפסט קודם לחזרה במקרה של כשל. לא נדרש שינוי DB או אתחול האתר. עד שאין חבילה חתומה ומאומתת, אין לפרסם מניפסט שמציע התקנה.

## בדיקות מכשיר

יש לבדוק התקנה מעל הגרסה הקיימת ללא הסרה, שימור הגדרות/תבניות/היסטוריה, הרשאת מקור התקנה, דחייה וניסיון חוזר, ניתוק בהורדה, מעבר לרקע, חסימת התקנה בזמן מענה או שינויים שלא נשמרו, הפעלה מחדש של המענה ללא שליחה חוזרת. אין בדיקת שליחת הודעות אמיתיות כחלק מעבודת העדכון.

ב־Windows בדיקת FileProvider מאמתת את הגדרת התיקייה, הרשאת קריאה וחסימת קבצים פרטיים; יצירת URI בפועל דורשת Android/Unix ובדיקה פיזית. אין להסיק מבדיקות Robolectric שהתקנה במכשיר כבר בוצעה.

## בסיס ושינויים

הבסיס הוא 0.4.0, commit d48d05b, הכולל את מסלולי הטלפון ו־Meta. שם החבילה ומסדי הנתונים נשמרו. תוספת ניהול העדכון נמצאת ב־AppUpdateClient, AppUpdates, UpdateFileProvider ו־update_paths.xml. MainActivity מציג את הכרטיס ואת מספר הגרסה. CloudDelivery/ReplyDispatcher מדווחים על פעולה פעילה כדי לחסום התקנה במהלכה; DeliveryEditor מדווח על עריכה שלא נשמרה. מנגנון השליחה אינו מוחלף.

נוספו 10 בדיקות לכל גרסת בנייה: 8 לקובץ/מניפסט/זהות/חתימה/נתונים ו־2 לבדיקת גרסה שקטה, חסימת מתקין והתנהגות ללא רשת. יחד עם 86 הבדיקות הקיימות, 96 בדיקות בכל flavor — 192 בסך הכול. כל בדיקות הרשת משתמשות בתשובות מלאכותיות ולא בנמענים אמיתיים.
